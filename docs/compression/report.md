# 本周主要工作

## 1. 厘清 EP 推理的通信瓶颈到底在哪

- 多份工作量化了 all-to-all 占比：COMET 测得可占整模型执行时间约 47%，LSH-MoE 训练期约 45%。结合我的硬件（8×RTX 4090 无 NVLink），通信瓶颈比 H100 NVLink 更重。

## 2. 砍掉“通信感知负载均衡”方向

最初设想是把负载均衡扩展成“通信感知的负载均衡”（联合优化负载 + 通信局部性）。调研后决定放弃，理由有二：
- 我的负载均衡实验发现，更换不同策略对性能优化的差别较小；
- 该子方向已较拥挤（Occult / GRACE-MoE / MoETuner / ExFlow 都已联合优化放置与通信），差异化空间小。

## 3. 系统调研“纯降通信量”的已有方法

把已有工作分成 4 类，核心判断如下：
- **overlap / kernel 融合**（Tutel/COMET/Flux/EPS-MoE/DeepEP hook）：无损系统优化，与压缩正交可叠加。
- **量化**（DeepEP FP8、MoRI MXFP4/FP8）：已做到 dispatch=FP4、combine=FP8 的产线水平；只压“每元素位宽”，不利用 token 间冗余或低秩结构。
- **低秩 / 学习式 payload 压缩**（SCoMoE、LSH-MoE、LatentMoE）：**全部是训练期或需预训练的架构改动**，没有人在冻结模型上、推理期做。
- **自适应 top-K**（Ada-K/Top-P/DA-MoE）：都在改激活专家的“数量”，没人改“每个 token 传多少比特”（码率自适应）。

## 4. 精读 2 篇可直接参考方法的论文

- **LSH-MoE（NeurIPS 2024）**：提供了“先压缩 payload → 专家算压缩表示 → combine 端用残差误差补偿还原”的三段式骨架；其消融显示去掉误差补偿 confusion 涨约 0.3 点，说明**误差补偿是有损方法做到近无损的命门**。但它是训练期、让权重适应压缩。
- **Communication Compression for TP Inference（arXiv 2411.09510）**：虽是张量并行不是 MoE，但它**证明了“推理期 + 冻结模型 + 压缩卡间 activation”这条路可行**（选定激活压缩 3.5–4.5×、TTFT 降至多 2×、精度退化可忽略），可尝试转移至 MoE EP 模型。

# 阻塞与风险

- **最大不确定性：低秩这条路成不成立，完全取决于 MoE dispatch 激活是否近似低秩**。如果激活的奇异值谱很平（有效秩接近 d），低秩压缩一压就掉精度，方向要退到纯 combine 稀疏化。
- **精度风险集中在 combine 端**：专家输出误差直接进 hidden state，可能比 dispatch 端更敏感，需非对称设计（combine 端更保守）。
- **硬件依赖**：结论强依赖 8×4090 无 NVLink 这一前提；换高带宽互联收益会缩小。
