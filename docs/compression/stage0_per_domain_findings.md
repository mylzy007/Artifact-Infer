# Stage 0 跨域实验：低秩性是否依赖标定数据域？（Qwen3-30B-A3B）

## 一句话结论

**域差异很大：代码域（lcc / repobench_p）最低秩，模板化检索（passage_ret）和中文（dureader）最不低秩，差距可达 EV@d/4 0.05–0.20。** 在 **layer 2 + 单一代码/数学域**上，4× 压缩判据（EV@d/4 ≥ 0.90）**通过**；但**所有中层（12, 24, 36）无论什么域都不通过**。换数据集**部分有救**——若部署场景是代码补全/数学这种窄域，低秩这条路活了一半；如果是通用多域服务，结论不变。

## 1. 实验设置（与 v2 唯一差异：按域切开）

- 模型：Qwen3-30B-A3B BF16，4×4090，d=2048
- 每个域：16 chunk × 512 tokens = **8192 tokens（N/d=4，well-conditioned for SVD）**
- 7 个域，共 57 344 tokens 一次性 forward 完成
- 探针层：2, 12, 24, 36, 46

域选择（覆盖代码 / 自然语言 / 中文 / 模板化）：

| 域 key | 来源 | 性质 |
|---|---|---|
| `lcc` | LongBench lcc.jsonl | 多语言长代码补全 |
| `repobench_p` | LongBench repobench-p.jsonl | 纯 Python 代码 |
| `gov_report` | LongBench gov_report.jsonl | 长英文政府报告 |
| `multifieldqa` | LongBench multifieldqa_en.jsonl | 混合领域问答上下文 |

## 3. 这次跨域实验改变了什么

### 3.1 改了什么

- **窄域明显比混合域低秩**——这是 LSH-MoE "相似 token 聚类" 直觉的**间接验证**：把语义同质的 token 收一起，谱就陡得多。
- **代码 / 数学窄域上，layer 2 的 4× 压缩首次出现"通过"**，第一次让"激进低秩"不再死路一条。
- **`lcc` 在所有层都通过 2× 压缩 90% 阈值**——是这次跑出来最干净的可行点。

### 3.2 没改的（仍然成立的负面结论）

- **中层（12–36）即使在最有利的代码域上也只到 EV@d/4 ≈ 0.76–0.81，仍不达 0.90 阈值。** 这块谱是模型结构层面的"自然秩"，靠换数据集救不回来。
- **任何域、任何层，到 0.99 方差都得留 ~80–90% 维**——"近无损"基本要求几乎不压。

### 3.3 直接的工程含义

- **"通用 MoE 推理" 用静态低秩压缩仍然不可行**（中层是瓶颈）；要做必须接受 5–25% 的方差损失，再靠 error feedback 把精度找回来。
- **"代码服务专项部署"是低秩压缩的甜点**：
  - 用 `lcc / repobench_p` 标定 → 全层 2× 压缩 + FP8 = 4× 总流量缩减、估计 PPL 掉点很小。
  - 这给了一个**差异化的论文角度**："domain-specialized low-rank compression for inference-time MoE EP"——单论文里强调"以前 LSH-MoE/SCoMoE/LatentMoE 都要训练期才能拿到这一点；我们在冻结模型 + 推理期、靠 domain calibration 也能拿到，且只对代码服务可用"。
- **域分档投影器**是这次实验最干净的 design 产出：在线根据 router/输入特征猜域 → 选不同 `P_down_domain`；离线对每个目标域跑一次 SVD 标定即可。

### 3.4 仍需补做的事

- **更长 calibration**：当前每域 8192 tokens（N/d=4），若关心可靠的 99.0% 谱估计可再加 4×。
- **跨模型对照**：在 DeepSeek-V2-Lite 上重跑跨域。如果 DeepSeek 在中层也代码域低秩、其它域不低秩，则"代码域低秩"是 MoE 通用性质；如果只 Qwen3 这样，那它是 Qwen3 训练数据偏置。
- **per-expert × per-domain**：本次没拆 per-expert，下一步可以问"代码域 lcc 路由到的 top-1 专家，per-expert 谱是不是更陡"。

## 4. 给我（写周报）用的表述

> 上周判定 NO-GO 之后，本周补做"换数据集"对照实验：把混合标定换成单一窄域（代码 lcc / repobench_p、数学 gsm8k、长报告 gov_report、混合 QA、中文 dureader、模板检索 passage_ret），每域 8192 token，覆盖 5 个层。
>
> 结果：**代码域低秩性最好，所有层在 2× 压缩下保 91–98% 方差；layer 2 上还能做到 4× 压缩保 92–93% 方差**。中文和模板化检索域最差，layer 2 上 4× 压缩只能保 79%。
>
> 修正后的方向判断：(1) **通用 MoE 推理上的激进低秩压缩仍不可行**——中层"自然秩"高，换数据集救不回来；(2) **代码 / 数学窄域上低秩压缩可用，是个差异化的论文角度**："冻结模型 + 推理期 + 域分档投影器" 可拿到 2× 全层低秩压缩，叠加 FP8 → 4× 总流量缩减；(3) **主线仍走 combine 端稀疏化（Direction B）**，它不依赖域；低秩作为"代码服务专项"的辅助路径。
