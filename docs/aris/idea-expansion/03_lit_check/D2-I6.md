# Lit-check: D2-I6 — Decode fast-path kernel scheduler

## Idea recap
Decode-only kernel-launch graph bakes K, drop=off, replica-map into static CUDA graph; switch at phase boundary.

## Keywords searched
- MoE CUDA graph kernel specialization decode launch overhead static replay 2024-2025
- megakernel LLM decode

## Top candidates
1. **KTransformers** (Chen et al., SOSP'25, paper PDF cannot be web_fetched but existence + mechanism confirmed via independent third-party summaries citing the SOSP version) — **explicitly encapsulates entire MoE decode phase into a single CUDA Graph instance via CUDA-based spinning; up to 1.23× speedup.** Direct kill.
2. **Event Tensor / ETC** (arXiv:2604.13327, verified=YES this trace title) — unified megakernel abstraction for dynamic LLM inference; covers MoE among other ops; not MoE-decode-specific but adjacent.
3. **DuoServe-MoE** (arXiv:2509.07379) — two-stream CUDA pipeline for prefill prefetch.
4. **FlashDMoE / FlashMoE** (arXiv:2506.04667, verified=YES via D1 collision) — single-kernel MoE with fused dispatch/compute/combine pipelining.
5. **PyGraph** (arXiv:2503.19779) — robust CUDA Graph compiler support in PyTorch.

## Closest 3 priors + differences
- **KTransformers** — direct prior: single CUDA Graph for full MoE decode. **No meaningful differentiation**.
- **FlashDMoE** — fused single-kernel MoE with pipelining. **Diff**: training+inference forward, but the decode-specialization angle overlaps.
- **Event Tensor / ETC** — megakernel for full pipeline. **Diff**: dynamic shapes, not MoE-decode-specific.

## Has been published? **完全 (KTransformers SOSP'25)**

## Collision rating: **完全撞**

## Additional missed priors (from GPT collision QC, all verified=YES)

- **Blink** (Siavashi et al., April 2026, arXiv:2604.07609) — persistent GPU kernel removing CPU from inference steady state, doing batching/scheduling/KV management on-device. More aggressive than D2-I6.

## Conclusion: **放弃**
