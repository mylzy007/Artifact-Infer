# Lit-check: D1-I5 — Payload-bottleneck-cut expert replica placement

## Idea recap
Min-max-flow / bottleneck-cut placement objective: minimize *worst per-peer dispatch+combine bytes* (not sum, not balance) on the per-layer expert-to-rank graph, subject to per-rank VRAM.

## Keywords searched
- expert placement minimax bottleneck min-max-flow MoE serving 2024-2025
- "worst-case communication" MoE placement
- Topology-aware MoE expert placement (D2 trace)

## Top candidates considered (all verified)
1. **MoETuner** (Go & Mahajan, 2025, arXiv:2502.06643, verified=YES via D1 trace) — ILP placement minimizing inter-GPU communication + balancing token workloads. *Sum-bytes / balance* objective, not min-max bottleneck.
2. **Cluster Topology-Driven Placement** (2025, arXiv:2508.09229, verified=YES via D2 trace) — ILP topology-aware placement minimizing network traffic. Sum-bytes objective.
3. **Patterns behind Chaos** (Wu et al., 2025, arXiv:2510.05497, verified=YES this trace) — prefill-aware expert placement from data-movement forecasting; abstract doesn't explicitly use min-max objective.
4. **Semantic Parallelism** (ICLR'26, arXiv:2503.04398, verified=YES via D1 trace) — token-expert co-scheduling reducing a2a; not min-max objective per se.
5. **Scaling Multi-Node MoE via Activation Patterns** (2026, arXiv:2604.23150, verified=YES via D1 trace) — workload-aware micro-batch grouping + locality placement.
6. **FasterMoE** (PPoPP'22, dl.acm.org/.../3503221.3508418, verified=YES via D1 trace) — topology-aware gate, dynamic shadowing. Balance + locality loss, not min-max.

## Closest 3 priors + differences
- **MoETuner** — closest in *machinery* (ILP placement). **Diff**: D1-I5 uses min-max bottleneck objective vs MoETuner's balance. Falsification (Jaccard distance ≥0.2 between solutions) lets us measure the diff empirically.
- **Cluster Topology-Driven** — closest in *traffic-minimization motivation*. **Diff**: sum-based objective vs min-max.
- **Patterns behind Chaos** — closest in *prefill-aware*. **Diff**: that paper forecasts movement patterns for prefetch/placement; D1-I5 rewrites the loss function.

## Has been published? **no** (for the specific min-max bottleneck-cut formulation)
ILP-style expert placement is published (MoETuner, Cluster Topology). The *min-max* formulation with worst-per-peer-bytes objective is not directly published in our search window.

## Collision rating: **接近但有差异**
Placement-via-ILP is crowded; min-max bottleneck objective is the differentiator. Empirically falsifiable by Jaccard distance from MoETuner's solution.

## Novelty space remaining
- **Min-max objective** (proven to choose different placements than balance/sum)
- **Worst-per-peer bytes** as edge cost (calibrated from router histogram)
- Composition with drop (drop reduces total, placement reduces worst-edge)

## Conclusion: **可做**
Strongest D1 idea entering Stage B. Required next step: small offline pilot showing two ILPs (sum vs max) select different layouts at equal VRAM (Jaccard ≥0.2). If they coincide on this hardware, idea collapses to MoETuner.
