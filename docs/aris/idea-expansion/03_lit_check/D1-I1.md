# Lit-check: D1-I1 — Payload-aware top-K routing (byte-cost-augmented router)

## Idea recap
Add `λ·byte_cost(e | rank)` to router logit at inference time; no retraining.
Mechanism shifts router toward byte-cheap expert when scores are close.

## Keywords searched
- MoE token routing locality-aware communication cost augmented router 2024-2025
- MoE expert placement replica communication aware EP all-to-all (D1 trace)
- "router score perturbation" / "communication-aware routing" inference

## Top candidates considered (all web_fetch-verified across this and earlier traces)
1. **LocMoE+** (Li et al., 2024, arXiv:2406.00023 → resolves to "Expert-Token Resonance MoE: Bidirectional Routing", verified=YES) — affinity-driven token-choice/expert-choice bidirectional routing during *training* with locality loss. Modifies the routing distribution itself, not score with byte cost.
2. **LSH-MoE** (Nie et al., NeurIPS 2024, arXiv:2411.08446, verified=YES via D1 trace) — locality-sensitive hashing *transforms the payload*; does not modify router score.
3. **ExFlow** (Yao et al., IPDPS 2024, arXiv:2401.08383, verified=YES via D1 trace) — exploits cross-layer expert affinity in *placement*, no router score change at inference.
4. **Semantic Parallelism** (Li et al., ICLR 2026, arXiv:2503.04398, verified=YES via D1 trace) — co-scheduling tokens/experts to reduce a2a; offline static plan rather than inference-time router perturbation.
5. **MoETuner** (Go & Mahajan, 2025, arXiv:2502.06643, verified=YES via D1 trace) — ILP placement to balance load; routing is regular top-K.
6. **Scaling Multi-Node MoE via Activation Patterns** (Bambhaniya et al., 2026, arXiv:2604.23150, verified=YES via D1 trace) — micro-batch grouping + locality placement; not router-score change.

## Closest 3 priors + differences
- **LocMoE+/ETR** — close in *spirit* (locality-aware), but training-time bidirectional routing, not inference-time score perturbation. **Diff**: D1-I1 is post-hoc, no weight updates, λ tuned offline.
- **LSH-MoE** — close on *communication-cost* axis but mechanism is payload hashing, not router score augmentation. **Diff**: orthogonal operator; in principle composable.
- **Semantic Parallelism** — close on *minimize a2a* objective but co-schedules data flow at placement granularity. **Diff**: D1-I1 is per-token runtime, not per-deployment static plan.

## Has been published? **partial**
Locality-aware MoE routing exists (LocMoE family); inference-time score perturbation by per-peer byte cost without retraining is not directly published in our search window.

## Collision rating: **接近但有差异**
Pattern is in the air (LocMoE family, ExFlow, MoETuner). The specific contribution (λ·byte_cost as a *runtime, post-hoc* router score addition with *per-peer pending bytes* as the cost signal) is not directly duplicated, but novelty is incremental.

## Novelty space remaining
- **Per-peer pending bytes** as the cost signal (not just static expert-rank distance, which is what LocMoE/ExFlow use).
- **Composition with existing token drop**: byte savings stack.
- **Zero retraining + Pareto λ-sweep characterization** at inference.

## Conclusion: **需调整**
Recast contribution as "*inference-time, per-peer-pending-bytes* router score perturbation that composes with drop"; explicitly differentiate from LocMoE+ (training-time bidirectional) and LSH-MoE (payload transform). If shaped this way, defensible as a runtime knob study, not a new MoE architecture.
