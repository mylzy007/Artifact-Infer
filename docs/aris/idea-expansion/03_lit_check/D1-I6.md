# Lit-check: D1-I6 — Combine-asymmetric drop with ‖g·o‖ criterion

## Idea recap
Drop only on combine path (post-expert), using `‖g_e,t · o_e,t‖₂` (gated output magnitude) as the per-(expert,token) importance criterion. Quality-asymmetry: combine drop is informed by *post-expert* signal, dispatch drop only by pre-expert router score.

## Keywords searched
- MoE expert pruning skipping ACL ICLR 2024-2025 (D1 trace)
- post-expert importance token-wise MoE drop
- expert dropping criteria study MoE

## Top candidates considered (all verified)
1. **Not All Experts are Equal** (Lu et al., ACL 2024, arXiv:2402.14800, verified=YES via D1 trace) — task-agnostic / task-specific *whole-expert* pruning + skipping. Decision unit = expert (not (expert, token)).
2. **Finding Fantastic Experts** (Jaiswal et al., 2025, arXiv:2504.05586, verified=YES via D1 trace) — unified benchmark on expert-dropping criteria; informs methodology but per-expert.
3. **Capacity-Aware Inference** (arXiv:2503.05066, verified=YES via D1 trace) — token drop / reroute on straggler signal; pre-expert.
4. **SERE** (arXiv:2602.07616, verified=YES via D2 trace) — similarity-based expert *re-routing* during batch decoding; reroutes rather than drops.
5. **Turn Waste into Worth (Rectify-Router)** (Zeng et al., 2024, arXiv:2402.12399, verified=YES via D5 trace) — handles dropped tokens & padding; pre-expert mechanism.
6. **Tutel/MegaBlocks/DeepSpeed-MoE** family — symmetric or no-drop.

## Closest 3 priors + differences
- **Not All Experts are Equal** — closest *decision-criterion* family. **Diff**: D1-I6 is per-(expert, token) combine-only drop with ‖g·o‖ importance; theirs is whole-expert.
- **Finding Fantastic Experts** — methodology to evaluate importance criteria. **Diff**: a benchmark not a system; D1-I6 uses ‖g·o‖ specifically and tests *byte-side* asymmetry.
- **Capacity-Aware Inference** — token drop at inference. **Diff**: pre-expert (straggler signal) vs post-expert (output magnitude).

## Has been published? **no**
Per-(expert, token) combine-only drop with post-expert magnitude criterion is not directly published. Adjacent decision-unit & criterion work exists.

## Collision rating: **互补**
Different decision unit (per (expert, token)), different criterion (post-expert ‖g·o‖), different drop location (combine only). Real adjacency to per-expert pruning but not duplicate.

## Novelty space remaining
- **Quality-asymmetry** as the contribution (vs latency claim)
- **‖g_e,t · o_e,t‖₂** as the post-expert importance signal
- Pareto front: combine-only vs symmetric drop at fixed combine bytes

## Conclusion: **可做**
Defensible novelty if reframed as "quality-asymmetry between dispatch- and combine-side drop at fixed combine-byte budget" (already done in revision). Falsification clear: if combine-only doesn't Pareto-dominate symmetric drop, the asymmetry is illusory.
