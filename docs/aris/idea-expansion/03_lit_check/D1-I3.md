# Lit-check: D1-I3 — FP8/INT8 dispatch+combine payload quantization

## Idea recap
Quantize per-token dispatch payload (and symmetric combine) to FP8 E4M3 with per-token scale + stochastic round; only on the a2a hop; receiver dequantizes before expert GEMM.

## Keywords searched
- MoE all-to-all FP8 INT8 quantization dispatch combine kernel 2024-2025
- "quantized all-to-all MoE" (D1 trace)
- DeepEP FP8, MXFP4 MoE communication

## Top candidates considered
1. **FP8-Flow-MoE** (Sun et al., 2025, arXiv:2511.02302, verified=YES) — FP8 *training* recipe with casting-free dataflow; abstract explicitly focuses on training, not inference-time a2a. Composition with drop not discussed.
2. **LSH-MoE** (NeurIPS 2024, arXiv:2411.08446, verified=YES via D1 trace) — payload compression via LSH for *training*; orthogonal compression operator.
3. **FP8 PTQ (Kuzmin et al., 2023)** (arXiv:2309.14592, verified=YES via D5 trace) — generic FP8 post-training quantization for LLMs; does not target a2a.
4. **FireQ** (arXiv:2505.20839) — INT4-FP8 GEMM kernel; not a2a payload focus.
5. **DeepEP** (DeepSeek, GitHub library) — already supports FP8 dispatch in production; not an academic paper but operational reference.
6. **MXFP4 MoE training** (search-result-only, no specific paper) — abstracts mention FP4 a2a compression in training.

## Closest 3 priors + differences
- **FP8-Flow-MoE** — same target precision and tensor location, but exclusively *training-side* (loss/gradient stability is the focus). **Diff**: D1-I3 is *inference-only*; no gradient interaction; composition with token-side drop is the new bit.
- **DeepEP FP8 dispatch** (deployment, not paper) — already FP8 dispatch exists in production NCCL EP / DeepEP path. **Diff**: D1-I3 frames FP8 as *one lever among three* (drop / K / FP) and studies composition + byte-budget framing, not just enablement.
- **LSH-MoE** — different compression operator (hashing vs quantization); training-side.

## Has been published? **partial**
FP8 on MoE a2a is in production (DeepEP, NCCL EP). Training-side FP8/MXFP4 with a2a compression is published (FP8-Flow-MoE). The *inference + composition-with-drop* study is not directly published.

## Collision rating: **接近但有差异**
FP8 a2a is in the air; standalone novelty is low. Salvage = compositional / cost-model framing (D1-I3 + drop + D1-I4 controller).

## Novelty space remaining
- Inference-only framing (not training stability)
- Composition with token-level drop (additive byte savings)
- Per-token stochastic-round vs static scale comparison
- Required only if other D1 work needs FP8 as a controller action

## Conclusion: **需调整**
Reframe as "*inference FP8 a2a as a controller action* composable with drop (D1-I4)" rather than standalone. As standalone, novelty is too low; FP8 part collides with DeepEP/FP8-Flow-MoE. Keep as a *building block*, not a paper centerpiece.
