# Lit-check: D4-I5 — L*-aware admission queue

## Idea recap
Two queues by predicted regime (drop-eligible vs no-drop); front router by predicted L_recv regime.

## Keywords searched
- LLM admission control queue routing regime
- D3-I5 priors (admission)

## Top candidates (all verified)
1. **SCORPIO** (arXiv:2505.23022) — heterogeneous-SLO admission + queue + batch.
2. **BrownoutServe** (arXiv:2507.17133) — MoE+SLO+bursty.
3. **SLOs-Serve** (arXiv:2504.08784, verified=YES via D3 collision) — multi-SLO dynamic allocation.
4. **JITServe** (arXiv:2504.20068, verified=YES via D3 collision) — SLO-aware imprecise info.
5. **Nitsum** (arXiv:2605.05467, verified=YES via D3 collision) — tiered-SLO TP-aware.

## Closest 3 priors + differences
- **SCORPIO** — admission + queue. **Diff**: D4-I5 splits by *predicted L_recv regime*, not by SLO class.
- **SLOs-Serve** — multi-SLO dynamic. **Diff**: D4-I5 regime = MoE-specific signal.
- **JITServe** — SLO-aware imprecise. **Diff**: D4-I5 is regime-based not goodput-based.

## Has been published? **partial**
Same prior space as D3-I5; substantial cross-D5 overlap (D4-I5 is regime-label version, D3-I5 is byte-budget version).

## Collision rating: **接近但有差异 / cross-overlap with D3-I5**
D3-I5 already downgraded to "互补 as feature"; D4-I5 has same fate.

## Conclusion: **降级 / 合并到 D3-I5**
Functionally equivalent to D3-I5 at admission layer; recommend merging the two into a single "MoE-regime-aware admission feature".
